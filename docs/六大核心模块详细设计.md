# 六大核心模块详细设计方案
## 1.文档解析模块
- 功能：PDF/Word/网页/图片类多源文档解析，拆分文本、表格、图片附属内容
- 实现思路：基于成熟开源解析库封装工具类，网页资源配套通用爬虫能力，优化请求头、动态UA池解决反爬、接口限流问题
- 输出：碎片化原始文本数据，存入MongoDB原始文档库

## 2.信息抽取模块（LLM驱动）
- 功能：依靠大模型API从自由文本中抽取关键实体、属性信息
- 实现思路：提示词工程分层设计，区分通用抽取Prompt与自定义业务Prompt，通过Prompt迭代调优模型输出准确率；兼容多厂商大模型接口
- 优化点：批量调用限流、请求异常重试，避免大模型接口调用失败导致整批任务作废

## 3.结构化转换模块
- 功能：将大模型返回的零散文本统一收敛为固定Schema的JSON/JSONL格式
- 实现思路：配置字段映射规则，正则+BS4辅助修正不规则输出，统一字段命名规范

## 4.质量检查模块
- 校验维度：字段完整性校验、数据内容准确性校验、内容重复度校验
- 落地方案：
  1. 规则校验：必填字段非空、字段格式正则匹配
  2. 去重方案：MD5摘要算法全局数据去重
  3. 模型复检：低置信数据二次送入大模型复核，不合格数据单独归档异常库

## 5.任务调度模块
- 核心：自定义`task_runtime_status.json`作为任务状态记录载体，记录批次ID、处理进度、失败节点、已完成分片
- 断点续传逻辑：任务启动时读取状态文件，跳过已完成分片，仅处理未完成任务，实现任务中断自愈；Redis缓存运行中任务状态，MySQL持久化历史批次信息
- 批量管控：批次初始化、分批调度、进度轮询、结果批量导出

## 6.插件系统模块
- 设计目标：低代码拓展业务处理逻辑，无需改动主框架源码
- 支持：自定义抽取Prompt插件、自定义清洗规则插件、自定义文档解析插件，插件配置文件外置，按需启用禁用
